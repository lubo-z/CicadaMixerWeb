# CicadaMixer Web 开发文档

## 文档地位

本目录是 CicadaMixer Web 的开发基线（single source of truth）。产品、架构、接口、数据模型、交互或验收标准发生变化时，必须先更新本目录中的相关文档，再修改程序。

若文档之间出现冲突，按以下优先级处理：

1. 已确认的产品需求与验收标准；
2. 已接受的架构决策记录（ADR）；
3. 接口与数据契约；
4. 交互和实现说明；
5. 原项目说明及其他背景资料。

发现冲突时不能靠代码“选一个实现”，应先修正文档并在变更记录中说明。

## 文档先行流程

每一项开发变更遵循以下顺序：

1. 在需求文档中描述用户可观察到的变化，并给需求分配稳定编号。
2. 若影响架构、数据或接口，更新对应文档；重大取舍新增 ADR。已否决或被当前文档完全覆盖的 ADR 直接删除，必要历史只保留在变更记录中。
3. 在 `CHANGELOG.md` 的“未发布”章节记录变更。
4. 评审并确认文档不存在矛盾。
5. 才开始改程序和测试；提交或合并请求应引用需求编号。
6. 用验收文档验证实现，并在完成后更新路线图状态。

仅修正文案错字且不改变含义时，可以直接修改文档并记录在变更日志中。

## 术语

- **候选选择**：界面中用户当前勾选、但尚未应用到播放中的蝉种。
- **活动组合**：当前实际播放或等待恢复播放的蝉种集合。
- **自动会话**：用户在“时节自动 + 实时 + 自动更新”下点击播放后启动的持续调度会话。
- **媒体可用**：浏览器能够请求、解码并开始播放媒体音轨。
- **本地时间**：浏览器所在设备的日期、时间和时区，不是服务器时间。
- **浏览器级设置**：只保存在当前浏览器、当前站点源的用户偏好，不写回后端，也不跨设备同步。
