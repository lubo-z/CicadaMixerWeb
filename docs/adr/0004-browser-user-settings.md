# ADR-0004：浏览器级用户设置

- 状态：已接受
- 日期：2026-07-29
- 决策者：项目负责人
- 关联：[ADR-0003](./0003-json-config.md)

## 背景

自动混音同时播放数量和实时检查间隔需要由使用者调整。若每次调整都写回后端 `config.json`，会把个人偏好变成全局配置，在多用户部署中互相影响，并要求新增写 API、并发控制、文件权限和安全边界。

这两项值不属于生态资料或服务器运行状态。后端仍需要限制安全、性能和交互上可接受的范围，并提供一致的初始默认值。

## 决策

1. `backend/config/config.json` 只声明设置约束：
   - `autoMix`：`defaultTracks`、`minTracks`、`maxTracks`；
   - `liveRefresh`：`defaultMinutes`、`minMinutes`、`maxMinutes`、`stepMinutes`。
2. 首版约束为自动混音默认 6、范围 1–10；实时检查默认 30 分钟、范围 5–120 分钟、步长 5 分钟。
3. 后端启动时校验约束并通过 Catalog API 原样提供；不保存或推断当前用户值。
4. 前端把当前值保存在同源 `localStorage` 的版本化对象 `cicadaMixer.preferences.v1` 中。
5. 前端每次加载 Catalog 后逐项重新校验本地值；无效值回退至服务端默认值并规范化存储。
6. 首版不增加修改配置或保存设置的 API，也不进行账户、设备或浏览器之间的同步。
7. 自动上限变化立即影响预览，下一次播放或实时检查才影响活动组合；实时间隔变化只重新安排计时器，不中断活动声音。

## 理由

- 用户之间互不影响，符合这两项值的个人偏好属性；
- 后端配置保持只读，避免写 API、认证、竞争写入和配置损坏风险；
- 服务端仍能通过范围控制同时媒体请求数和计时频率；
- 本地持久化无需账户，刷新后仍能恢复；
- Catalog 约束变化后重新校验，避免旧设置绕过新的服务端限制。

## 代价

- 设置不会跨浏览器或设备同步；
- 清除网站数据会恢复默认值；
- 隐私模式或存储被禁用时只能保留当前页面会话中的值；
- 修改后端默认值不会覆盖仍然合法的既有浏览器偏好。

## 被否决的方案

### 每次修改写回 `config.json`

这会把一位用户的选择应用给全部用户，并引入服务端写权限、并发和安全问题，不符合只读配置架构。

### 只保存在 React 内存

实现简单，但刷新即丢失，不满足浏览器级设置的持久体验。

### 使用用户账户和数据库

可以跨设备同步，但显著扩大首版范围；当前产品明确不包含账户系统。

## 复审条件

- 产品加入账户和跨设备同步；
- 多租户需要按组织下发不同策略；
- 设置扩展为敏感或需要审计的数据；
- 浏览器存储限制使本地持久化不能满足目标平台。
